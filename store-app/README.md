# تطبيق إدارة المحل (Store App)

تطبيق فلاتر (Flutter) لإدارة محل صغير أو متوسط، يعمل على **ويندوز** و**أندرويد** من نفس الكود، ويخزّن بياناته محلياً (SQLite) على كل جهاز — بدون حاجة لإنترنت أو سيرفر.

## المزايا

- **تسجيل دخول لكل موظف**: كل موظف له رمز دخول (code) وكلمة مرور خاصة به، ويُضاف من شاشة الإعدادات من قبل المدير فقط.
- **صلاحيات**: حساب "مدير" يرى كل الشاشات بما فيها الإعدادات، وحساب "كاشير" يرى المنتجات/المبيعات/الديون/التقارير فقط.
- **المنتجات**: إضافة/تعديل/حذف، مع سعر الشراء والبيع والكمية ووحدة القياس، وتنبيه عند اقتراب نفاد المخزون.
- **المبيعات**: نقطة بيع بسيطة (سلة مشتريات)، تدعم الدفع الكامل أو الجزئي — أي مبلغ غير مدفوع يتحول تلقائياً لدين على اسم الزبون، مع خصم الكمية من المخزون تلقائياً، وسجل لكل عمليات البيع.
- **الديون**: قائمة بكل الزبائن الذين عليهم ديون، مع إمكانية إضافة دين يدوي أو تسجيل دفعة، وسجل حركات كامل لكل زبون.
- **التقارير والأرباح**: إجمالي المبيعات وصافي الربح (حسب اليوم/الأسبوع/الشهر/الكل)، أكثر المنتجات مبيعاً، وتنبيهات نفاد المخزون.
- **الإعدادات**: إدارة الموظفين (إضافة/تعديل/تعطيل/حذف)، تحديد الصلاحية، وتغيير كلمة المرور.

بيانات كل جهاز محلية ومستقلة (لا مزامنة بين الأجهزة في هذا الإصدار).

### الدخول الافتراضي

عند أول تشغيل يتم إنشاء حساب مدير تلقائياً:

- **الرمز:** `1111`
- **كلمة المرور:** `1111`

غيّر كلمة المرور فوراً من شاشة **الإعدادات** بعد أول دخول.

## هيكلة المشروع

```
lib/
  models/     نماذج البيانات (موظف، منتج، عملية بيع، زبون، حركة دين)
  db/         db_helper.dart — قاعدة بيانات SQLite (إنشاء الجداول + كل عمليات القراءة/الكتابة)
  state/      session.dart — حالة تسجيل الدخول الحالية
  screens/    شاشات التطبيق (دخول، منتجات، مبيعات، ديون، تقارير، إعدادات)
  utils/      أدوات مساعدة (تشفير كلمات المرور)
```

قاعدة البيانات تُستخدم عبر `sqflite` على أندرويد، وعبر `sqflite_common_ffi` على ويندوز — بنفس الكود.

## متطلبات التشغيل

- [Flutter SDK](https://docs.flutter.dev/get-started/install) (قناة stable).
- لبناء أندرويد: Android Studio SDK/تجهيزات أندرويد (`flutter doctor` يوضح الناقص).
- لبناء ويندوز: يجب التنفيذ من جهاز ويندوز فيه Visual Studio (Desktop development with C++) مُثبّت.

## التشغيل والتطوير

```bash
cd store-app
flutter pub get
flutter run            # يشغل التطبيق على أي جهاز/محاكي متصل
```

## البناء للإصدار النهائي

### أندرويد (APK)

```bash
cd store-app
flutter build apk --release
# الناتج: build/app/outputs/flutter-apk/app-release.apk
```

### ويندوز (تنفيذ من جهاز ويندوز)

```powershell
cd store-app
flutter build windows --release
# الناتج: build\windows\x64\runner\Release\
```

بعد البناء انسخ محتويات مجلد `Release` كاملاً (وليس فقط ملف exe) لتوزيع التطبيق على أجهزة ويندوز أخرى.

## الاختبار

يوجد اختبار تكامل (integration test) في `integration_test/app_test.dart` يشغّل التطبيق الحقيقي فعلياً ويتحقق من: تسجيل الدخول، إضافة منتج، عملية بيع بدفع جزئي (ويتأكد أن الدين انتقل تلقائياً لشاشة الديون)، صحة أرقام التقارير، إضافة موظف جديد من الإعدادات، وتسجيل دخول ذلك الموظف مع التأكد أن شاشة الإعدادات مخفية عنه. تم تشغيل هذا الاختبار فعلياً (عبر نسخة سطح مكتب لينكس كبديل مؤقت لويندوز أثناء التطوير) ونجح بالكامل. لتشغيله بنفسك:

```bash
# على جهاز ويندوز (بعد تفعيل دعم سطح المكتب):
flutter drive --driver=test_driver/integration_test.dart --target=integration_test/app_test.dart -d windows

# على جهاز/محاكي أندرويد متصل:
flutter test integration_test/app_test.dart
```

## ملاحظات

- تم التحقق من المشروع بأمر `flutter analyze` (بدون أخطاء)، `flutter test`، واختبار التكامل أعلاه. لم يتم إجراء بناء APK/EXE نهائي (release) في بيئة التطوير هذه لعدم توفر Android SDK وVisual Studio بها؛ نفّذ أوامر البناء أعلاه من جهاز يحوي الأدوات المطلوبة.
- لإضافة موظف جديد: من شاشة الإعدادات (تظهر فقط لحساب المدير) اضغط "إضافة موظف"، وحدد رمزاً فريداً وكلمة مرور وصلاحية (مدير/كاشير).
